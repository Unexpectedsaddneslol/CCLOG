# Контр-Культура — заметки по проекту

Сайт-визитка OSINT-проекта «Контр-Культура» (в духе Bellingcat) со встроенной
скрытой админ-панелью. Чёрно-белый строгий дизайн, длинная скроллящаяся
главная + отдельные полные страницы по разделам (часть разделов — просто
якоря на главной, см. «Структура» ниже).

## Стек

Next.js 16 (App Router) + TypeScript, Prisma 7 + SQLite (через
`@prisma/adapter-better-sqlite3`), Framer Motion (параллакс/анимации),
Tiptap (рич-текст редактор в админке, с поддержкой вставки и ресайза
картинок), pdf.js (просмотр PDF-отчётов в браузере) + `pdf-parse` (серверное
извлечение куска текста PDF для превью-карточек на страницах списков).

## Как запустить на новой машине

```bash
npm install
npx prisma generate
npm run dev
```

Открыть http://localhost:3000. Порт задан в `.claude/launch.json` (3000);
если занят — освободить процесс или поменять там.

Если после `npm install` часть пакетов (better-sqlite3, prisma, esbuild)
не установилась из-за allow-scripts — `npm approve-scripts <пакет>`
(список уже частично зафиксирован в `package.json` → `allowScripts`).

## Git / деплой

Репозиторий — приватный на GitHub: **github.com/2reneku/counter-culture**.
Продакшен — Railway, SQLite остаётся (не переезжали на Postgres — на
Railway есть постоянный диск, этого достаточно для одного инстанса).

Что реально нужно на Railway, чтобы всё завелось:

- **Volume**, смонтированный на `/data`.
- Переменные окружения сервиса (ничего из `.env`/`.env.local` туда не
  едет — оба файла в `.gitignore`, их нужно продублировать руками):
  - `SQLITE_DATABASE_URL=file:/data/dev.db` (раньше называлась
    `DATABASE_URL` — переименовали, потому что в том же Railway-проекте
    уже была другая служба с таким именем и они конфликтовали).
  - `UPLOADS_DIR=/data/uploads` — без этого файлы, загруженные через
    админку (картинки/PDF), пишутся в `public/uploads` контейнера, который
    эфемерный и стирается на каждом передеплое; БД при этом остаётся
    (она на volume) и ссылается на файлы, которых уже нет. Смотри
    `lib/uploadsDir.ts` и `app/uploads/[filename]/route.ts` — раздача
    файлов идёт через свой route handler, а не статику из `public/`,
    именно чтобы поддержать путь вне `public/`.
  - `ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET` — как в `.env.local`
    локально, см. «Доступ в админку» ниже.
- `package.json`:
  - `build` = `prisma migrate deploy && prisma generate && next build`.
  - `start` = `prisma migrate deploy && next start` — миграции гоняются
    ещё раз при старте, не только при сборке: на некоторых PaaS (в т.ч.
    похоже на Railway) volume не обязательно примонтирован во время
    build-шага, только во время реального запуска контейнера — если
    прогнать `migrate deploy` только на билде, SQLite-файл может
    создаться не на volume, а в эфемерном build-слое.
- `next.config.ts` → `serverExternalPackages: ["pdfjs-dist", "pdf-parse"]`
  — без этого Turbopack пытается забандлить воркер pdf.js внутрь
  серверных SSR-чанков и падает на резолве `pdf.worker.mjs` (сообщение
  вида `Cannot find module '.../chunks/ssr/pdf.worker.mjs'`) — любой
  запрос, который трогает `lib/pdfSnippet.ts` (т.е. любая страница со
  списком расследований/статей), валился с 500.
- Публичные страницы со списками (`/`, `/services`, `/investigations`,
  `/articles`, а раньше и `/tools`/`/followers`/`/join`) имеют
  `export const dynamic = "force-dynamic"`. Без этого Next статически
  собирает их один раз при билде — новый контент, добавленный через
  админку, появляется в самой админке (она всегда фетчит живьём), но не
  на публичной странице, даже после F5, пока не пересоберёшь проект.

## ВАЖНО: что не попадёт в git и надо переносить руками

`.gitignore` исключает:

- **`.env` / `.env.local`** — `SQLITE_DATABASE_URL` (локально) и секреты
  админки (`ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET`). Без них пароль
  в админку не подойдёт и сессии не расшифруются — см. ниже, как
  перегенерировать.
- **`dev.db`** (лежит в КОРНЕ проекта, не в `prisma/dev.db`! —
  `SQLITE_DATABASE_URL="file:./dev.db"` резолвится относительно cwd, а не
  относительно `prisma/`, это не сразу очевидно) — сама база SQLite со
  всем текущим контентом. Потеряешь файл — потеряешь контент, останутся
  только `prisma/seed.ts`-заглушки.
- **`public/uploads/*`** — картинки/PDF, загруженные через админку
  (локально; в проде см. `UPLOADS_DIR` выше).
- **`node_modules`**, **`app/generated/prisma`** (генерируется
  `prisma generate`), `.next/`.

`public/fonts/*` — **не** в `.gitignore`, попадут в git как обычно.

## Доступ в админку

1. Кликнуть **16 раз** по лого в шапке, быстро (окно ~1.4с между кликами) —
   откроется поле пароля.
2. Пароль хранится только как bcrypt-хэш в `.env.local`
   (`ADMIN_PASSWORD_HASH`). Я его нигде не записывал в открытом виде — если
   потерян/файл не перенёсся, сгенерировать новый:

   ```bash
   node -e "console.log(require('bcryptjs').hashSync('НОВЫЙ_ПАРОЛЬ', 12))"
   ```

   Вставить результат в `.env.local` вместо старого `ADMIN_PASSWORD_HASH`.
   `ADMIN_SESSION_SECRET` — любая случайная строка (можно
   `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`).

   **Ловушка:** bcrypt-хэш выглядит как `$2b$12$...` — Next.js прогоняет
   `.env.local` через `dotenv-expand` и трактует `$2b`/`$12`/`$RyJ...` как
   ссылки на переменные окружения, молча схлопывая их в пустую строку
   (кавычки вокруг значения не спасают — dotenv-expand разворачивает `$`
   уже после того, как dotenv снял кавычки). Результат — «Неверный
   пароль» с виду верным хэшем в файле. Нужно экранировать каждый `$` как
   `\$`: `ADMIN_PASSWORD_HASH=\$2b\$12\$...` (без кавычек вокруг всего
   значения).
3. Сессия живёт 3 часа, httpOnly-cookie (`lib/session.ts`).
4. Логика подбора пароля ограничена (`lib/auth.ts`, таблица
   `LoginAttempt`) — 5 неудачных попыток за 15 минут блокируют IP.
5. Вкладка «Посетители» в админке (`components/admin/VisitLogViewer.tsx`,
   API — `app/api/records/visits/route.ts`) показывает журнал заходов
   (IP, User-Agent, язык браузера, путь, время) из таблицы `VisitLog` —
   см. «Журнал посещений» ниже про то, как эта таблица наполняется.

## Журнал посещений

Каждый заход на публичную страницу пишется в таблицу `VisitLog`
(ip/userAgent/language/path/createdAt) через `proxy.ts` в корне проекта
(в Next.js 16 это переименованный `middleware.ts` — файл называется
`proxy.js|ts`, а не `middleware.js|ts`, но по сути то же самое; см.
`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md`).
Начиная с Next 16 Proxy по умолчанию выполняется в Node.js-рантайме (не
Edge), поэтому в нём можно напрямую использовать Prisma/better-sqlite3 —
раньше (до 15.5) это было бы невозможно без экспериментального флага.

- Запись пишется через `event.waitUntil(...)`, не блокируя ответ.
- `config.matcher` в `proxy.ts` исключает статику (`_next/*`, `assets`,
  `fonts`, `uploads`, `favicon.ico`, `icon.png`) и API-роуты, а также
  (через `missing`) запросы с заголовками `next-router-prefetch`/
  `purpose: prefetch` — иначе наведение курсора на `<Link>` (RSC-префетч)
  считалось бы отдельным визитом.
- Язык браузера — первый тег из `Accept-Language` (до первой запятой и
  `;q=`), а не весь заголовок целиком.
- Во вкладке «Посетители» есть только чтение (постранично, по 100
  записей) и кнопка «Очистить журнал» (`DELETE /api/records/visits`) —
  никакого редактирования отдельных записей, в отличие от остальных
  вкладок админки (`EntityEditor`), там это не нужно.

## Структура

- `app/` — роуты. `app/page.tsx` — главная (превью всех секций, включая
  «Инструменты»/«Последователи»/«Вступить к нам» — у них НЕТ отдельных
  страниц, шапка ведёт на якоря `/#tools`, `/#followers`, `/#join` на
  главной, не переходит никуда). Отдельные полные страницы остались только
  у `/investigations`, `/articles`, `/services`; детальные —
  `/investigations/[slug]`, `/articles/[slug]`.
- `app/api/` — `session` (логин админки), `records/[entity]` (CRUD для
  админки), `upload` (загрузка файлов, пишет в `UPLOADS_DIR`).
- `app/uploads/[filename]/route.ts` — раздача загруженных файлов (см.
  «Git / деплой» → `UPLOADS_DIR`).
- `components/` — секции публичного сайта; `components/admin/` — сама
  админ-панель (`AdminPanel`, `EntityEditor`, `RichTextEditor` на Tiptap,
  `ResizableImage.ts` — кастомный Tiptap-node для картинок в тексте с
  ручкой ресайза в углу, `DropUpload` — drag&drop/выбор файла).
- `lib/` — `prisma.ts` (клиент), `session.ts`/`auth.ts` (админ-сессии),
  `content.ts` (запросы для публичных страниц, там же довешивается
  `contentSnippet` — кусок текста тела/PDF для превью-карточек),
  `pdfSnippet.ts` (серверное извлечение текста первой страницы PDF через
  `pdf-parse`), `uploadsDir.ts`, `entities.ts` (whitelist полей для
  админского CRUD), `text.ts` (`truncate`, `stripHtml`), `slug.ts`.
- `prisma/schema.prisma` — модели: Investigation, Article, Tool, Service,
  Partner, Follower, SiteSettings, AdminSession, LoginAttempt, VisitLog
  (журнал посещений, см. «Журнал посещений» выше).
- `proxy.ts` (корень проекта) — логирует каждый заход в `VisitLog`, см.
  «Журнал посещений» выше.
- `prisma/seed.ts` — стартовые/тестовые данные:
  `npx prisma db seed` (перезаписывает Tool/Service/Partner/
  Investigation/Article/Follower, SiteSettings — upsert).

## Дизайн — на что не наступить при доработке

- Чёрно-белый, без скруглений (`* { border-radius: 0 !important }`).
  Тени — разрешены, добавлены по отдельному запросу заказчика.
- `html { zoom: 1.215 }` в `app/globals.css` — весь сайт намеренно
  увеличен (как зум браузера); было `1.35`, уменьшили на 10% по просьбе
  заказчика. Это осознанное решение, не баг — но см. ниже про параллакс,
  `zoom` не бесплатный и путает как минимум Framer Motion.
- Шрифты (`public/fonts/`, подключены в `app/layout.tsx` через
  `next/font/local`):
  - Заголовки (`--font-heading`) — `ArialNova-Light.ttf`, вес 300
    (реально Light-начертание файла, не синтетическое утоньшение).
  - Основной текст (`--font-body`) — `ArialNovaCond.ttf` (400) +
    `ArialNovaCond-Bold.ttf` (700, реальный жирный файл — раньше жирность
    называемых элементов (`.report-row__title`, `.list-row__name` и т.д.)
    была браузерным fake-bold, т.к. второго начертания не было; теперь
    оба начертания зарегистрированы в одном `localFont({ src: [...] })`).
  - Навигация в шапке + email в футере (`--font-mono`) —
    `ArialMonoMTProRegular.ttf` (раньше был `CartographMonoCF-Regular.ttf`,
    файл остался в `public/fonts/`, но больше нигде не подключён).
  - `HelveticaNeue-Thin.otf`/`HelveticaNeue-Medium.otf`/`ArialNova.ttf`/
    `CartographMonoCF-Regular.ttf` — не используются, остались на диске.
- Шапка — `position: fixed`, высота 56px; компенсация —
  `body { padding-top: 56px }` в globals.css, и `scroll-padding-top: 56px`
  на `html` (нужно для якорных ссылок `/#tools` и т.п., чтобы заголовок
  секции не залезал под шапку при переходе). Меняешь высоту шапки — обнови
  оба места.
- Навигация в шапке — при ширине ≤1000px превращается в гамбургер-меню
  (`.header-nav-toggle`/`.header-burger`/`.header-dropdown` в
  `Header.tsx`/globals.css) вместо переноса ссылок на вторую строку.
- Параллакс в Hero (`components/Hero.tsx`) — **не используй
  `useScroll({ target })` от framer-motion для scroll-linked анимаций на
  этом сайте.** Наступили на грабли: `target`-режим меряет границы через
  `getBoundingClientRect()`, а это уже отмасштабированное `zoom`-ом число,
  в то время как реальный скролл (`window.scrollY`) в CSS `zoom` не
  участвует — два числа из разных систем координат, диапазон анимации
  получался в разы короче реального (на мобиле было особенно заметно:
  параллакс «заканчивался» после пары сантиметров скролла). Текущее
  решение — `useScroll()` без `target` (даёт сырой `scrollY` в реальных
  пикселях) + `ref.current.offsetHeight` (не `getBoundingClientRect` —
  `offsetHeight` остаётся в том же немасштабированном пространстве, что и
  `scrollY`) как верхняя граница диапазона. Картинка-контейнер специально
  больше секции (`top: -20%, height: 150%`), чтобы translate+scale не
  оголяли чёрный фон секции по краям при доскролле до конца.
- Карусель последователей (`components/FollowersMarquee.tsx`) — важный
  нюанс на будущее: расстояние между кружками задано через
  `margin-right` на самих кружках, а **не** через `gap` на flex-треке.
  Если вернуть `gap`, анимация `translateX(-50%)` даёт видимый скачок в
  точке склейки цикла (проверено на практике, `gap` считается не так, как
  кажется, и сдвиг перестаёт совпадать с границей копии списка). Число
  повторов списка (`repeats` в компоненте) всегда округляется до чётного
  — тоже для бесшовности лупа.
- `.container` — `max-width: 1024px` (не 960, не 1300 — были обе версии в
  процессе правок). `.container--wide` — без max-width (edge-to-edge);
  для `ServiceRows` есть доп. модификатор `.container--wide-bounded`
  (`max-width: 1400px`) — фото в услугах позиционируются
  `position:absolute` относительно строки, а строка без ограничения ширины
  бесконечно растёт при очень широком/отдалённом экране, и фото уезжает
  от текста — cap на 1400px чинит это, не трогая вид на обычных экранах.
- **`<Reveal>` (`components/Reveal.tsx`) — голый `motion.div` без своих
  стилей.** Если оборачиваемый им элемент держится на `width: 100%`
  (например строка в списке, которую нужно растянуть на всю ширину
  колонки), а родительский flex-контейнер имеет `align-items` отличный от
  `stretch` (по умолчанию) — например `center` — то сам `Reveal`-wrapper
  схлопывается по контенту вместо растяжения на всю ширину, и `100%`
  внутри него резолвится в размер по контенту, а не в реальную ширину
  колонки (итог — элементы разной ширины, ряд «съезжает»). Если нужно
  центрировать/выравнивать содержимое внутри `Reveal`-обёрнутого блока —
  центрировать через `justify-content` на самом блоке, а не через
  `align-items` на родителе; либо явно прокинуть `className` в
  `<Reveal className="...">` (проп это умеет).
- **Border-box и «доступная ширина» контейнера.** У `.container`
  (`box-sizing: border-box` через глобальный `*`-ресет) `getComputedStyle`
  `.width` включает паддинг — это НЕ то же самое, что реальная ширина,
  доступная детям внутри (она меньше на паддинг с обеих сторон). При
  расчётах «влезет ли ряд в одну строку без переноса» (flex-wrap) нужно
  вычитать паддинг из этого числа ещё раз, а не использовать его напрямую.

## Тени / свечение / шум

Никаких файлов-теней (`*back.png`, `*shadow.png`, `noise.png`) в коде нет —
всё чистый CSS. `public/assets/tools/noise.png` и
`public/assets/partners/noise.png` остались на диске, но нигде не
подключены.

- **Шум/зерно** — процедурный SVG-фильтр `#site-grain` (`feTurbulence` +
  `feColorMatrix`, объявлен в `app/layout.tsx`, рендерится 0×0 и
  aria-hidden). Применяется через `filter: url(#site-grain)` — не картинка,
  генерируется браузером на лету.
- **Свечение под круглыми лого** (инструменты/партнёры,
  `.list-row__icon-glow` в `app/globals.css`) — размытая и осветлённая
  копия самой иконки (`blur()` + `brightness()`), а не отдельный файл.
  **Важно:** этому слою обязательно нужны `border-radius: 50% !important`
  и `overflow: hidden` — без них он квадратный div под круглым лого,
  торчит углами.
- `.section-noise` (тень/шум под заголовком секции у `ListSection`) —
  **полностью убрана** по просьбе заказчика (раньше существовала в CSS, но
  нигде фактически не подключалась; теперь удалена и из CSS, и из
  компонента). Если попросят вернуть — это была радиальная маска поверх
  `#site-grain`, концентрированная к центру секции.
- **Услуги** (`components/ServiceRows.tsx`) — вообще без тени/свечения:
  фото заказчика (`sim.jpg`/`docs.jpg`/`books.jpg`, см. ниже) уже сами по
  себе с мягким ореолом. Есть только `mask-image: radial-gradient(...)` на
  `.service-row__image-crop` — плавно гасит квадратные края картинки по
  всем четырём сторонам. **Нюанс:** рамка `.service-row__image-wrap` —
  3:2 (шире чем выше), поэтому у эллипса маски проценты по X и Y разные
  (`62% 93%`, не `62% 62%`) — иначе верх/низ гаснут резче, чем бока.

## Картинки услуг (`public/assets/service/`)

Заказчик несколько раз подряд присылал новые рендеры для трёх услуг
(«Физические номера» / «Расследования» / «Наставничество») — по одной
фотке на услугу, узнаваемы по сюжету (sim-карты / стопка документов /
шапка+книги), не по имени файла. Сейчас лежат как
`sim.jpg`/`docs.jpg`/`books.jpg`, пути прописаны в `Service.icon` в БД
**и** в `prisma/seed.ts` (держать синхронно). Если пришлют ещё раз —
подставлять по содержимому картинки, а не по имени файла.

Эти фото — большие квадратные рендеры (~4000×4000), почти целиком чёрные,
маленький объект по центру с уже вшитым мягким ореолом.

## Известные ограничения / что можно доделать

- Иконка инструмента Catharsis (`public/assets/tools/catharsis.png`) —
  единственный доступный файл с этим значком уже содержит вшитую в
  картинку подпись-текст; отдельной чистой иконки нет. Заменить через
  админку, когда пришлют нормальный файл.
- Аватарки «последователей» (`public/assets/followers/f1–f12.svg`) —
  сгенерированные заглушки (буква в кружке), не реальные фото/логотипы
  (см. `scripts/generate-follower-avatars.mjs`).
- Поле `Service.shadow` (в схеме, в whitelist `lib/entities.ts`, в
  админке есть поле загрузки — «Подложка (shadow)») больше нигде не
  читается на фронте (у услуг нет отдельного слоя тени, см. выше). Можно
  оставить как есть или снести миграцией при генеральной уборке схемы.
- PDF-отчёты у расследований/статей — раньше рендерились прямо на странице
  через pdf.js в `<canvas>` (`components/PdfViewer.tsx`), убрано по просьбе
  заказчика: осталась только кнопка «Скачать PDF →» (`.btn`,
  `target="_blank"` на файл). Причина не только в желании заказчика — сам
  in-page просмотр был проблемным: на части iPhone (iOS < 18) валился с
  «Не удалось отобразить PDF» из-за `Promise.withResolvers()`, которого
  pdf.js требует, а старые iOS Safari не поддерживают; там же, где
  показывался, из-за незаданного `devicePixelRatio` при рендере canvas
  картинка была нечитаемо размытой на телефонах. `pdfjs-dist` как прямая
  зависимость сайта убран из `package.json` — серверное превью-извлечение
  текста (`lib/pdfSnippet.ts`) использует `pdf-parse`, у которого свой
  собственный `pdfjs-dist` во вложенных `node_modules`, не связанный с
  этим.
- SQLite в проде — рабочее решение ТОЛЬКО пока один инстанс Railway с
  volume (см. «Git / деплой»). Если когда-нибудь понадобится несколько
  инстансов/serverless — переезжать на Postgres (Prisma это позволяет
  почти без переписывания кода, поменять datasource + адаптер).

## Специфика окружения (эти версии новее, чем в обучающих данных модели — не полагайся на память, если что-то не работает как «обычно»)

- **Next.js 16** — `cookies()`, `headers()`, `params` в route handlers —
  все асинхронные (`await cookies()`, `const { slug } = await params`).
  При сомнениях смотри `node_modules/next/dist/docs/` в этом проекте —
  версия у API реально другая, чем большинство обучающих примеров.
- **Prisma 7** — `PrismaClient` теперь **обязательно** требует driver
  adapter, даже для SQLite (см. `lib/prisma.ts`,
  `@prisma/adapter-better-sqlite3`). Генератор в schema — `prisma-client`
  (не `prisma-client-js`), клиент генерируется как TS-исходники в
  `app/generated/prisma`, а не биндинг в `node_modules`. Конфиг — в
  `prisma.config.ts` (использует `SQLITE_DATABASE_URL`, не `DATABASE_URL`),
  не только в `.env`/datasource url.
- **Turbopack + pdfjs-dist/pdf-parse** — оба пакета обязаны быть в
  `next.config.ts` → `serverExternalPackages`, иначе Turbopack пытается
  забандлить воркер pdf.js в серверные SSR-чанки и падает на его резолве
  (см. «Git / деплой»).
